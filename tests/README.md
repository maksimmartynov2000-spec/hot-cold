# Проверки

Ловят то, что не видно в коде: наложения элементов, нечитаемый текст,
неработающие кнопки, сломанные переводы, расхождение игры и базы.

## Как запустить

```bash
cd tests
npm install
npm test          # основные проверки игры
npm run layout    # вёрстка на пяти размерах экрана
npm run offline   # работа без интернета
npm run e2e       # игра против настоящей базы
npm run db        # база: миграции, файлы проверки, сценарии
```

## Что чем проверяется

- `run.js` открывает `index.html` напрямую из файла и подменяет Supabase
  заглушкой из `helpers.js`: интернет и живая база не нужны.
- `layout.js` — то же на телефонах, планшете и компьютере.
- `offline.js` поднимает локальный сервер, потому что service worker не
  работает с `file://`.
- `e2e.js` собирает базу через `db/run.sh` и гоняет игру против неё — так
  видно, что игра и функции базы понимают друг друга.
- `db/run.sh` проверяет, что все миграции из `supabase/migrations`
  применяются с нуля по порядку и повторно, что во всех файлах из
  `supabase/checks` только ✔, и прогоняет сценарии `db/test_*.sql` на базе
  из `db/00_base.sql` и миграций. Каждый сценарий — в транзакции с
  откатом, так что они не влияют друг на друга.

Часть правил записана дважды — в игре и в базе (пояса «горячо/холодно»,
бонусы, аватары, боты, награды лиг). Скрипты `db/*_from_js.js` каждый раз
заново достают эти таблицы из кода игры (`index.html` и `js/`, см.
`db/game_source.js`), а сценарии сверяют их с базой.
Получившиеся `.csv` в git не хранятся.

Что уже поймали эти проверки: переключатель языка, наезжавший на строку статуса
и блокировавший кнопку; чёрный текст на тёмном фоне в окне подтверждения;
очистку полей формы при показе ошибки; повторное начисление очков за уже
угаданное число; тёмный шов внизу страницы при длинной истории попыток.
