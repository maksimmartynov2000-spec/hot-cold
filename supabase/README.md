# База (Supabase)

## Папки

| Где | Что |
|---|---|
| `migrations/` | изменения базы, пронумерованы в порядке применения |
| `checks/` | проверка, что миграция применилась; номер — как у миграции |
| `admin/` | разовые служебные скрипты (сброс PIN ученику) |

## Как применить новую миграцию

1. Supabase → SQL Editor → вставить файл из `migrations/` целиком → Run.
2. Там же вставить файл из `checks/` с тем же номером → Run. В колонке
   «итог» везде ✔.
3. Только после этого выкладывать игру: новая версия ждёт, что база уже
   обновлена.

Если не уверены, что миграция прошла, — её можно прогнать ещё раз, вреда не
будет. Но только последнюю: старая миграция вернёт функции базы к прошлым
версиям.

Проверка с номером N смотрит, что стоит миграция N. Более поздние миграции
её не ломают: `tests/db/run.sh` прогоняет все проверки на базе со всеми миграциями
и требует ✔ везде.

## Как добавить миграцию

- Следующий свободный номер: `034_что_делает.txt`. Проверку к ней —
  `checks/034_что_делает.sql`.
- Файл должен применяться повторно без ошибок: `create or replace`,
  `if not exists`, `drop … if exists`.
- В `tests/db/run.sh` ничего вписывать не нужно — миграции берутся по номерам.

## С нуля

Миграции 001–007 писались, когда база уже была: таблицу `game_config` тогда
создали вручную, и её исходного определения нет. Поэтому для нового проекта
сначала нужен `tests/db/00_supabase.sql` — он создаёт эту таблицу, — потом все
миграции по порядку. `tests/db/run.sh` каждый раз проверяет, что так база
собирается без ошибок.
